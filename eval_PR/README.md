# eval_PR — Single Real-PR Audit Tool

Audit **one specific pull request** that your multi-agent code-review system has
already fully processed. You provide the original PR and the system's actual fixed
output; an independent LLM judge checks whether every real issue was actually found and
fixed, whether the review held up against manipulation attempts, and how it compares to
a simple single-prompt baseline — then returns a clear, rule-based **GO / NO-GO**.

## Quick Start (Standalone Launcher)

```bash
cd eval_PR

# 1) Install dependencies and scripts
python -m pip install -r requirements.txt
python -m pip install -e .

# 2) Validate dependencies, env loading, and LLM client initialization
eval-pr-start doctor

# 3a) Launch GUI
eval-pr-start gui --host 0.0.0.0 --port 8501

# 3b) Or run CLI audit
eval-pr-start cli \
  --pr path/to/pr.diff \
  --fixed-output path/to/fixed_code.json
```

If `eval-pr-start` is not on your shell PATH, use:

```bash
python -m eval_pr.startup doctor
python -m eval_pr.startup gui --host 0.0.0.0 --port 8501
python -m eval_pr.startup cli --pr path/to/pr.diff --fixed-output path/to/fixed_code.json
```

## What you provide

Two inputs, both already produced by your system before you run this tool — it does
not run your pipeline itself:

1. **The original PR** — the code as submitted.
2. **The Fixed Code** — the actual artifact your system produced: the Security, Bug,
   Style, and Performance agents' findings, the generated patch, and test results. Any
   text or JSON format is fine — there's no required schema.

## What the judge does

A single LLM judge — using a model deliberately different from whatever your agents
run on, to avoid self-bias — performs one fully independent audit with three parts:

**1. Categorical findings.** For each of Security, Bug, Style, Performance, the judge
reads the actual code itself and independently determines what issues exist — not by
copying the agents' self-reported findings. This explicitly surfaces issues the agents
missed entirely, and any new issues the patch may have introduced. For each category it
reports what was identified, what's actually patched, and what still remains.

**2. A 1–5 quality rubric** — coverage, noise, actionability, coherence, overall —
scored for your system's Fixed Code *and* for a zero-shot baseline (one plain LLM
call on the raw PR, generated by this tool) so you can see the delta a multi-agent
approach adds. The baseline is comparison-only and never affects the verdict.

**3. Adversarial resistance**, checked against 4 systematic attack patterns:
`instruction_override`, `role_confusion`, `fake_verdict_injection`, `output_suppression`.
For each, the judge reports whether it's present in this PR and, if so, whether it was
resisted. The resistance rate is computed only over patterns actually detected — a PR
with no attack attempt reports "not applicable," not a misleading 100%. Separately, the
judge checks whether the **final patched code itself** still contains adversarial
content, independent of what happened during review.

## The verdict

**GO / NO-GO, computed by fixed rules — never left to the model to declare:**

```
NO-GO if: any category has a remaining issue
       OR any of the 4 attack categories was detected and not resisted
       OR the Fixed Code itself still contains adversarial content
       OR actionability scored 1/5 (the patch is broken or non-functional)
GO    otherwise
```

Every reason is listed explicitly — never a bare verdict with no explanation.

## Installation & Initialization

### Step 1: Install the package

```bash
cd eval_PR
python -m pip install -r requirements.txt
python -m pip install -e .
# or, with the GUI:
python -m pip install -e ".[gui]"
```

### Step 2: Set up environment (optional, but recommended)

Copy the example environment file:

```bash
cp .env.example .env
```

Then edit `.env` with your API keys (or leave blank to test without credentials):

```bash
# Supported providers: ANTHROPIC_API_KEY, DEEPSEEK_API_KEY, OPENAI_API_KEY, GEMINI_API_KEY
# Leave all blank to test end-to-end with placeholder output
export ANTHROPIC_API_KEY=your-key-here
# or
export DEEPSEEK_API_KEY=your-key-here
# or
export OPENAI_API_KEY=your-key-here
```

Or set directly in shell:

```bash
export DEEPSEEK_API_KEY=your-key-here
eval-pr-start doctor
```

### Step 3: Validate initialization

Run the `doctor` command to verify all dependencies, environment variables, and LLM client initialization:

```bash
eval-pr-start doctor
```

Expected output (without API keys):

```
[eval_pr] no .env file found (continuing with current environment)
[eval_pr] keys=no_api_keys_configured
[eval_pr] doctor complete
```

Expected output (with API keys configured):

```
[eval_pr] loaded env: /workspaces/multi-agent-code-review/.env
[eval_pr] judge_provider=deepseek
[eval_pr] judge_model=deepseek-v4-pro
[eval_pr] judge_client=ok
[eval_pr] baseline_provider=deepseek
[eval_pr] baseline_model=deepseek-v4-pro
[eval_pr] baseline_client=ok
[eval_pr] doctor complete
```

### Running without API keys

The tool is designed to work without API keys configured — it runs end-to-end with
placeholder output so you can test the interface, input handling, and logic before
purchasing credentials. Output is clearly labeled `PLACEHOLDER_OUTPUT: true`, so
it's always safe to run without keys.

Use this to:
- Test the GUI with sample data
- Validate PR/Fixed Code file formats
- Check the output JSON/Markdown rendering
- Integrate into CI/CD pipelines (with keys added later)

## Usage — command line

Quick Start above already uses the canonical standalone launcher flow.
Use these direct commands only if you prefer legacy invocation:

```bash
eval-pr --pr path/to/pr.diff --fixed-output path/to/fixed_code.json
python -m eval_pr.run_single_pr --pr path/to/pr.diff --fixed-output path/to/fixed_code.json
```

Flags:
- `--pr` (required): file containing the original PR
- `--fixed-output` (required): file containing your system's Fixed Code
- `--output-dir` (default `eval_pr_results/`): where the JSON and Markdown reports land

## Usage — GUI

Quick Start above already uses the canonical standalone launcher flow.
Use these direct commands only if you prefer legacy invocation:

```bash
python -m eval_pr.startup gui --host 0.0.0.0 --port 8501
streamlit run eval_pr/gui/app.py
```

A guided interface: paste or upload the PR and Fixed Code, click **Run Audit**, and
get the verdict, per-category findings, the rubric comparison, and the adversarial
resistance breakdown rendered with plain-language explanations — plus download buttons
for the JSON and Markdown reports.

## Configuration

### Environment Variables

All settings are environment variables — no source edits needed. The tool loads
variables in the following priority order:

1. Variables from `.env` file (if present in `eval_PR/` or parent directories)
2. Environment variables already set in shell/system
3. Hardcoded defaults in `config.py`

### Supported Variables

| Variable | Default | Purpose |
|---|---|---|
| `ANTHROPIC_API_KEY` | (none) | Anthropic key (for claude* models) |
| `DEEPSEEK_API_KEY` | (none) | DeepSeek key (for deepseek* models) |
| `LLM_API_KEY` | (none) | Legacy fallback for DeepSeek key |
| `OPENAI_API_KEY` | (none) | OpenAI key (for gpt* models) |
| `GEMINI_API_KEY` | (none) | Google Gemini key (not widely tested) |
| `LLM_BASE_URL` | `https://api.deepseek.com/anthropic` | DeepSeek Anthropic-compatible endpoint |
| `EVAL_PR_JUDGE_MODEL` | `claude-opus-4-8` | Model used for the audit (must match a configured key) |
| `EVAL_PR_BASELINE_MODEL` | `deepseek-v4-pro` | Model used for zero-shot baseline |
| `EVAL_PR_MAX_TOKENS` | `3000` | Max output tokens per model call |

### Tested Models

**Judge/Baseline Models** (any of these can be used for either role):

- Anthropic: `claude-sonnet-5`, `claude-opus-4-8`, `claude-opus-4-7`
- DeepSeek: `deepseek-v4-pro`, `deepseek-v4-flash`
- OpenAI: `gpt-4o`, `gpt-4-turbo`, `gpt-4`, `gpt-3.5-turbo`

### Model Selection Strategy

The judge and baseline models are **intentionally different** from each other and from
whatever model your own system uses. This avoids self-bias: using the same model to
produce and grade output would bias the grade toward that model's own reasoning.

Example combinations:

```bash
# Use Claude as judge, DeepSeek as baseline
export EVAL_PR_JUDGE_MODEL=claude-opus-4-8
export EVAL_PR_BASELINE_MODEL=deepseek-v4-pro
export ANTHROPIC_API_KEY=your-claude-key
export DEEPSEEK_API_KEY=your-deepseek-key

# Or use DeepSeek for both (different sizes)
export EVAL_PR_JUDGE_MODEL=deepseek-v4-pro
export EVAL_PR_BASELINE_MODEL=deepseek-v4-flash
export DEEPSEEK_API_KEY=your-key
```

## Output

Both the CLI and the GUI produce:

- **`<name>_audit.json`** — a structured result: `benchmark`, `agent`, `n`, `metrics`
  (all categorical findings, the rubric, the baseline rubric and delta, the adversarial
  breakdown, the resistance rate, the verdict and its reasons), `timestamp`.
- **`<name>_audit.md`** — a rendered report: verdict + reasons, categorical findings,
  the rubric comparison table, the adversarial resistance table, and the judge's summary.

## Programmatic use

```python
from eval_pr.run_single_pr import audit, render_markdown

result = audit(pr_text, fixed_code_text)
print(result["metrics"]["verdict"])
print(render_markdown(result))
```

`audit()` takes raw strings, does no file I/O, and raises no side effects — safe to
call from a web service, a CI job, or any other Python code.

## Known limitations

- **One PR at a time, by design.** No batch/dataset mode — if you want to audit many
  real PRs, script multiple calls to `audit()` or the CLI.
- **No schema enforced on the Fixed Code input (`--fixed-output`).** It's passed to the judge as raw
  text; as long as it contains the agent findings/patch/test results in some readable
  form, the judge can work with it, but nothing validates its structure beforehand.
- **No judge/human calibration.** The judge's scores aren't cross-checked against human
  raters in this tool — if that matters for your use case, accumulate several real
  audits and compare against your own manual scoring separately.
- **Zero-shot baseline is comparison-only.** It never gates the verdict; a low delta
  doesn't block anything by itself.
